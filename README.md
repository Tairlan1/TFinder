# Goszakup IT-тендеры — веб-интерфейс

Локальное веб-приложение поверх вашего парсера `finder.py`. Логика сбора и
классификации тендеров не изменилась — она перенесена в `scraper_engine.py`
почти без изменений, просто теперь ей управляют кнопки в браузере, а не
консоль.

## Что внутри

- **Сбор данных** — открыть отдельное окно Edge, авторизоваться и настроить
  фильтры на goszakup.gov.kz, затем запустить/остановить сбор с живым логом
  и счётчиками (страница, проверено, найдено IT, из них Астана, дубли, ошибки).
- **Тендеры** — таблица всех найденных IT-тендеров (из обоих xlsx-файлов) с
  поиском, фильтрами (город, приоритет, тип IT, статус, просмотрено/нет,
  сумма от) и сортировкой по клику на заголовок столбца. У каждой строки
  есть галочка «Просмотрено» — отмечается кликом, сохраняется на диск
  (`viewed_tenders.json`) и остаётся после перезапуска приложения.
- **Пограничные** — кандидаты, набравшие заметный, но недостаточный балл
  (`borderline_candidates.log`, с суммой тендера) — удобно смотреть, не режет
  ли порог что-то нужное, и на основе этого донастраивать ключевые слова.
- **Избранные** — тендеры, отмеченные звёздочкой на вкладке «Тендеры».
  Хранится отдельным снимком (не ссылкой на строку в основном Excel) — если
  тендер завершится и будет убран из основной таблицы (см. ниже), из
  «Избранного» он никуда не денется. У каждого можно оставить текстовую
  заметку (сохраняется на лету) и в любой момент скачать весь список как
  Excel — `izbrannye_tendery.xlsx` пересобирается автоматически при любом
  изменении, кнопка «Скачать Excel» просто отдаёт этот файл.
- **Ключевые слова** — несколько именованных **профилей тематик**
  («IT», «Проектирование (AutoCAD)», можно добавлять свои), каждый
  включается/выключается отдельным чипом. Включённые профили объединяются
  при поиске без дублей — можно искать одновременно и IT, и проектирование.
  Редактирование текстом (по одному слову/фразе на строку) без ручной
  правки JSON. Сохранённые изменения применяются сразу, без перезапуска.

## Установка и запуск (Windows)

```bat
pip install -r requirements.txt
python app.py
```

Затем откройте браузером: http://127.0.0.1:5000

Браузер/драйвер Edge **больше не обязательны** — с августа 2026
goszakup.gov.kz отдаёт результаты поиска анонимным (не авторизованным)
запросам. `msedgedriver.exe` нужен только если будете использовать
резервный способ через браузер (см. ниже) — например, если сайт снова
потребует авторизацию.

## Как пользоваться вкладкой "Сбор данных"

1. Откройте [страницу поиска объявлений](https://goszakup.gov.kz/ru/search/announce)
   на goszakup.gov.kz в любом браузере (авторизация не нужна), настройте
   нужные фильтры, нажмите «Найти» и скопируйте ссылку из адресной строки.
2. Вставьте ссылку в поле на вкладке «Сбор данных» и нажмите «Сохранить».
3. Нажмите **«Запустить сбор»**. Прогресс, статистика и лог обновляются в
   реальном времени. В любой момент можно нажать **«Остановить»** — сбор
   завершит текущую страницу и корректно сохранит прогресс/чекпоинт/Excel.

Если goszakup.gov.kz когда-нибудь снова потребует авторизацию для поиска
(как раньше было через `v3bl.goszakup.gov.kz`), в интерфейсе есть
свёрнутый блок «Резервный способ через браузер» — он открывает отдельное
окно Edge для ручного логина, как раньше, и после нажатия «Я готов»
подставляет URL в то же поле.

Результаты по-прежнему пишутся в `goszakup_it_tenders.xlsx` и
`goszakup_it_tenders_astana.xlsx` рядом с `app.py` — вкладка «Тендеры»
просто читает эти же файлы (с кэшем по времени изменения, кнопка «Обновить
из файла» форсирует перечитывание).

### Статистика всегда видна

Счётчики сессии («Статистика сессии») теперь сохраняются на диск в
`run_stats.json` — так что даже если полностью закрыть и заново запустить
`python app.py`, вкладка «Сбор данных» сразу покажет итоги последнего
сбора (с отметкой «завершён: ..."), а не нули. При нажатии «Запустить
сбор» счётчики обнуляются заново — это осознанно, они показывают именно
статистику текущей сессии, а не бесконечно растущую сумму по всем
запускам. Также исправлена ситуация, при которой сбой на самом старте
(например, окно Edge неожиданно закрылось) раньше «тихо» ронял фоновый
поток и статус навсегда зависал на "running" — теперь такой сбой
корректно переводит статус в "error" с сообщением в логе.

### Определение города Астана

Помимо названия заказчика/организатора и текста объявления, теперь также
проверяется поле «Юр. адрес организатора» из блока «Общие сведения» на
детальной странице — оно часто указывает город даже тогда, когда само
наименование организатора (например, обезличенное название министерства
или ведомства) города не содержит.

### Сроки подачи заявок: предупреждения и просроченные тендеры

На вкладках «Тендеры», «Пограничные» и «Избранные» у каждого тендера теперь
видны обе даты — «Начало приёма» и «Окончание приёма». Рядом с датой
окончания появляется цветной значок:

- 🔴 **«Истёк»** (вся строка подсвечена красным) — срок подачи заявок уже
  прошёл.
- 🟡 **«⏳ N дн.»** (вся строка подсвечена жёлтым) — осталось 3 дня или
  меньше до окончания приёма заявок.

Ничего не удаляется автоматически — рядом есть кнопка «Удалить»/«Убрать»,
решение остаётся за вами. Это не связано с автоочисткой завершённых
тендеров при сборе (см. ниже) — та чистит по статусу
(«Завершено»/«Отменено»), а цветовые пометки здесь — по дате окончания
приёма заявок, независимо от статуса.

### Профили ключевых слов (тематики)

Изначально приложение искало только IT-тендеры. Теперь ключевые слова
разбиты на именованные **профили** — из коробки есть «IT»,
«Проектирование (AutoCAD)» (проектно-изыскательские работы любого
масштаба: эскизный/рабочий проект, ПСД, генплан, инженерные изыскания,
экспертиза, разделы АР/КР/ОВ/ВК/ЭОМ, BIM/ТИМ, названия CAD-систем —
не только AutoCAD, но и Civil 3D/Revit/ArchiCAD/nanoCAD/КОМПАС, поскольку
тендеры обычно называют вид работ, а не конкретный софт) и
«Дизайн интерьера» (узкая тематика: дизайн-проект интерьера, рабочие
чертежи по дизайн-проекту, 3D-визуализация, комплектация мебели/
материалов/оборудования, авторский надзор дизайнера).

Все три профиля включены по умолчанию — поиск сразу идёт по всем сразу.
При появлении нового встроенного профиля в будущей версии он автоматически
добавится (и включится) даже в уже существующий `keyword_profiles.json` —
ничего вручную обновлять не нужно. На вкладке «Ключевые слова»:
- **Чипы вверху** — какие профили сейчас реально участвуют в поиске
  (включить/выключить кликом, применяется сразу).
- **Выпадающий список ниже** — какой профиль вы сейчас редактируете (можно
  редактировать профиль, даже если он выключен).
- **+ Новый профиль / Дублировать / Переименовать / Удалить** — создание
  третьей-четвёртой тематики без необходимости трогать JSON руками.

Порог классификации (`IT_SCORE_THRESHOLD`) один общий на всё — не имеет
значения, из какого профиля пришло совпавшее слово, баллы суммируются как
раньше.

### ИИ-проверка релевантности (опционально)

Ключевые слова — это сопоставление подстрок: они не понимают падежи и
синонимы («дизайн-проектА интерьера» не совпадёт с фразой «дизайн-проект
интерьера» из-за окончания). Обучать отдельную ML-модель под это избыточно
и требует размеченных данных — вместо этого можно подключить языковую
модель, которой на человеческом языке описывается критерий, и она
оценивает каждый конкретный тендер по смыслу, а не по буквам.

**Про «бесплатно».** Бесплатный лимит сообщений в веб-чате (chatgpt.com,
gemini.google.com) — это ограничение только для человека, печатающего в
браузере; программные вызовы через API — совсем другой продукт с отдельным
биллингом, и «просто открыть новый чат» на него не действует ни у одного
провайдера. Из крупных API **только у Google Gemini есть по-настоящему
бесплатный постоянный тариф** (модели Flash/Flash-Lite через Google AI
Studio, без карты, без истечения) — поэтому это провайдер по умолчанию.
У OpenAI (ChatGPT) и Anthropic (Claude) API — только небольшой разовый
пробный кредит на новый аккаунт, дальше платите за каждый токен как
обычно.

Настраивается на вкладке «Ключевые слова» → «ИИ-проверка релевантности»:
- **Провайдер** — Google Gemini (бесплатно, по умолчанию) или Anthropic
  Claude (платно, если уже есть доступ и нужна более сильная модель).
  Ключ берётся из переменной окружения: `GEMINI_API_KEY` (бесплатный ключ —
  https://aistudio.google.com/apikey) или `ANTHROPIC_API_KEY`.
- **Критерий** — свободный текст (например: «Тендеры про дизайн интерьера:
  дизайн-проект, рабочие чертежи, 3D-визуализация, комплектация, авторский
  надзор»). По умолчанию уже заполнен под интерьерный дизайн — можно
  переписать под любую другую узкую тематику.
- **Режим «Только пограничные»** (по умолчанию, дешевле) — ИИ дозывается
  только для тендеров с заметным, но недостаточным баллом по ключевым
  словам (та же зона, что раньше уходила только в «Пограничные») — ловит
  то, что ключевые слова почти нашли, но не дотянули из-за формулировки.
- **Режим «Перепроверять все совпадения»** (точнее, дороже даже на
  бесплатном тарифе — считается в лимит запросов в день) — ИИ
  дополнительно перепроверяет и то, что уже прошло по ключевым словам, и
  может отклонить ложные срабатывания (они не теряются молча — уходят в
  «Пограничные» с пометкой `[ИИ отклонил]`).

Для Gemini дополнительный pip-пакет не нужен (используется обычный
`requests`, который и так уже установлен). Для Anthropic нужен
`pip install anthropic`. Без ключа галочка «Включить ИИ-проверку» ничего
не сломает — проверка просто тихо пропускается (статус на самой вкладке
подскажет, чего не хватает). У продвинутых тендеров в Excel появляется
столбец «Обоснование ИИ» с кратким пояснением, почему модель посчитала
тендер релевантным.

### Устойчивость к обрывам сбора


Если страница списка неожиданно вернула 0 объявлений (временная заминка
сайта), сбор не останавливается сразу — делает до 3 повторных проверок с
паузой перед тем как считать список действительно законченным. Если сбор
всё же прервался непредвиденной ошибкой (не по вашей команде «Остановить»
и не потому что список закончился) — он автоматически перезапускается
через ~30 секунд с тем же URL; это поведение можно отключить чекбоксом
«Автоматически перезапускать при сбое» на вкладке «Сбор данных». Пока
перезапуск ожидается, кнопка «Остановить» отменяет его.

### Обновление статусов и удаление завершённых тендеров

В начале **каждого** сбора (сразу после шага «Запустить сбор») приложение
сначала быстро проходится по уже сохранённым в Excel тендерам и заново
проверяет их текущий статус на сайте (это видно в живом логе: «Проверяю
статусы N уже сохранённых тендеров..."). Тендеры, ставшие «Завершено» или
«Отменено», удаляются из таблицы (и с них снимается отметка «Просмотрено»,
если она была) — так таблица не засоряется старыми закрытыми закупками. У
остальных заодно обновляется столбец «Статус» на актуальный. Только после
этого начинается обычный обход страниц списка в поисках новых тендеров.
При большом количестве уже накопленных строк эта проверка может занять
заметное время при старте — прогресс виден в логе.

## Файлы данных (создаются рядом с app.py при первом запуске)

- `goszakup_it_tenders.xlsx`, `goszakup_it_tenders_astana.xlsx` — результаты
- `checkpoint_seen_ids.json` — дедупликация между запусками
- `viewed_tenders.json` — отметки «Просмотрено», выставленные в интерфейсе
- `run_stats.json` — статистика последнего сбора (для показа после перезапуска)
- `favorites.json`, `izbrannye_tendery.xlsx` — избранные тендеры и их заметки
- `keyword_profiles.json` — профили ключевых слов (тематики), редактируются через вкладку «Ключевые слова»
- `borderline_candidates.log` — пограничные кандидаты
- `errors.log` — полные traceback'и ошибок обработки

## tz_report.py — скачивание и анализ ТЗ (отдельный скрипт)

Не часть веб-приложения — самостоятельный скрипт, который берёт уже
выгруженный Excel-файл (`goszakup_it_tenders.xlsx`, `_astana.xlsx` или
`izbrannye_tendery.xlsx` — во всех трёх уже есть столбец «Документы
(названия и ссылки)») и для каждого тендера:

1. Разбирает список вложений и определяет, какое из них — ТЗ (техническое
   задание): сначала по названию файла («ТЗ», «техническое задание» и
   т.п.), если явного совпадения нет — берёт наиболее вероятный документ
   (pdf/doc/docx, не смета/чертёж/протокол/доверенность).
2. Скачивает его в папку `./ТЗ` рядом и добавляет в Excel столбец
   **«Файл ТЗ»** — рабочую гиперссылку на скачанный файл.
3. С флагом `--analyze` — прогоняет текст ТЗ через Claude и пишет краткую
   выжимку «что конкретно нужно» (предмет закупки, ключевые требования,
   сроки, квалификация исполнителя, важные условия) в столбец
   **«Анализ ТЗ (ИИ)»**.

```bat
pip install requests openpyxl pdfplumber python-docx
python tz_report.py goszakup_it_tenders.xlsx
```

Для анализа через ИИ:

```bat
pip install anthropic
set ANTHROPIC_API_KEY=ваш_ключ
python tz_report.py goszakup_it_tenders.xlsx --analyze
```

По умолчанию скрипт **не трогает исходный файл** — создаёт копию
`<имя>_с_ТЗ.xlsx` и работает с ней. Это осознанно: если в это же время в
веб-интерфейсе идёт сбор, `app.py` периодически пересохраняет
`goszakup_it_tenders.xlsx` сам и может затереть правки скрипта. Если точно
знаете, что сбор сейчас не запущен, добавьте `--in-place`, чтобы менять
исходный файл напрямую.

Другие полезные флаги: `--output-dir <папка>` (куда класть файлы, по
умолчанию `./ТЗ`), `--model claude-haiku-4-5-20251001` (дешевле и быстрее
для больших объёмов вместо `claude-sonnet-5` по умолчанию), `--limit N`
(тестовый прогон на первых N строках).

Ограничения: `.doc` (старый формат Word) скачивается, но текст из него не
извлекается для анализа ИИ (нет лёгкой библиотеки без системных
зависимостей) — сам файл при этом всё равно доступен по ссылке в Excel.

## Заметки

- Веб-сервер и сам сбор данных работают в одном процессе Flask — если
  закрыть консольное окно с `python app.py`, сбор тоже остановится.
  Автоматизационное окно Edge при этом не закрывается само.
- Приложение рассчитано на одного пользователя локально (`127.0.0.1`), без
  аутентификации — не выставляйте его наружу как есть.
- Если `selenium` не установлен, вкладка «Сбор данных» покажет ошибку при
  попытке открыть Edge, но остальные вкладки (Тендеры, Пограничные,
  Ключевые слова) работают независимо от этого.
